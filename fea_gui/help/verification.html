Verification against independent references

FEA Studio publishes a set of verification cases in which every result is compared with a reference that does not come from FEA Studio – a closed-form solution, a handbook or standard formula, a published solution, or the open-source solver MYSTRAN. For each case either a work is cited or – for an elementary relation – the first-principles relation is stated (the page marks such a case “relation stated, no work cited”). Each case shows the quantity, the source of the reference, the FEA Studio value, the difference, the tolerance and the mesh. The About dialog shows the current count (“N public verification cases, all within tolerance”).

Open the verification page (docs/verification/index.html in the program folder; the same tables are in README.md and results.csv next to it).

What the page contains

  • Tables by domain: linear statics, heat conduction and thermal stress, natural frequencies / buckling / dynamics, contacts, bolted and welded joints, fatigue, 3D-printed parts, beams and frames, 2D sections and shells, plasticity, mechanisms.
  • Reference type of each case: closed-form solution (Lamé, beam theory, Fourier's law, Euler buckling …), handbook or standard (stress concentration factors, convection correlations, EN / VDI / IIW rules), published solution (Hertz, Hetényi, Lekhnitskii, Miles, Neuber, Findley …) or MYSTRAN.
  • Cross-check against MYSTRAN: the same mesh (coarsened ×2) and nodal loads are solved by CalculiX and by MYSTRAN, which has its own assembly, boundary conditions and solver; the displacements and reactions must agree within 10-3.
  • MYSTRAN is not part of FEA Studio: it is a third-party program that no package carries and the installer does not download. To run the MYSTRAN cases yourself, download it from https://www.mystran.com (forum, Download) and save it as tools/mystran/mystran.exe (Linux tools/mystran/mystran) in the program folder. Without it, the cases whose reference is MYSTRAN are listed as “not run – MYSTRAN not installed” and the other cross-checked cases are marked “no MYSTRAN cross-check”. The rows on the published page come from a run with the program. Releases before 1.5.1 carried the program: an update from such a version removes that copy from tools/mystran (also one you saved there yourself under the same file name), so download it again; a copy saved after the update stays.
  • Run data: program version, date, CalculiX and MYSTRAN version, platform and run time. Cases that cannot run on the platform of the snapshot (for example the mortar contact of the Hertz case on Windows) are listed with the reason; they are never counted as passed.

How to read the tolerance: the finite-element result differs from a closed-form value by the discretisation error of the mesh, so each check has its own tolerance (displacements typically 1–3 %, stresses away from singularities 5 %). A case is within tolerance only when all its checks pass.

What is not published

A case without a reference from outside the program is not published: the program's own equilibrium and bookkeeping checks (also the rows of a published case that only repeat the applied load as a reaction), comparisons of two runs of the same model, wiring tests of input tables and checks of warning messages stay in the test suite (python -m pytest, verification.run_all) but are not presented as verification. Some published cases contain a few such consistency checks besides the referenced ones; they are not listed on the page but must pass too.

Note: a verified benchmark does not verify your model. Mesh convergence, boundary conditions and singularities of your own geometry must still be checked (see Mesh and Results).

Regenerating the page

  • python -m verification.run_public runs all published cases (about an hour; --quick leaves out the long contact cases; the impact case KK4 takes hours and runs only with --only KK4) and rewrites docs/verification/. It needs CalculiX and Gmsh (the Python packages: module “Verification”) and, for the MYSTRAN cases, MYSTRAN, which you download yourself (see above).
  • python -m verification.public_report only rewrites the page from the stored results of the last run.
  • The cases and their references are defined in verification/catalogue.py; the continuous-integration job “verification” runs the set on Linux (weekly the quick set, on every release tag the full set) and keeps the generated page as an artifact.
